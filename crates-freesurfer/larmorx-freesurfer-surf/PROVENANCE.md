# Provenance: larmorx-freesurfer-surf

**Replica: translated from FreeSurfer's source.** This crate holds `fs.surfio` (wave 3.1), `fs.surf` (wave 3.4), `fs.mars` (later) of the FreeSurfer
replica (`docs/freesurfer/waves.md` section 4): the surface structure and its I/O, with the metric properties every read computes (`fs.surfio`); the rest of the surface library: topology, values, volume-surface sampling, projections, the surface hash, realms, icosahedra, spherical maps, surface clusters, gcsa and the surface-gradient code (`fs.surf`). It is distributed under FreeSurfer's
licence (`LicenseRef-FreeSurfer`, `../LICENSE`: the FreeSurfer Software License with its required
preface), as part of the `larmorx-freesurfer` package (`docs/licensing.md`).

The upstream is FreeSurfer 8.2.0 (GitHub's `v8.2.0` archive, SHA-256
`bb1699f7655ebf0f3790db6a78af9532ea7c832c97fe5f71bfd9f0e9526d7e78`; `docs/freesurfer-plan.md`),
built for the official binaries with GCC 8.4.0 (`docs/freesurfer/variation.md`).

## Changes from the originals

- C's pointers are Rust values (`Option<Vec<T>>` for an array a function allocates, `None` for
  `NULL`; vertex numbers for pointers to vertices; `Arc` for the `MRIS_MP` arrays its copies share;
  `Opaque` for `void *`): reading a `NULL` array panics where FreeSurfer reads through a null
  pointer.
- A write through an `MRIS_MP` copy into one of its shared input arrays changes that copy only
  (FreeSurfer's copies share it; no FreeSurfer code writes one).
- The process-wide variables are fields of `SurfGlobals`, one value per run.
- Failed assertions end the call with FS-03's exit (`larmorx-freesurfer-core::diag::assert_failed`).
- `MRISmakeFloatPerVertex`'s array is 0 where FreeSurfer's `malloc` leaves it undefined; so are
  the distances' values `realloc` adds where FreeSurfer does not zero them.
- A vertex's distance buffer is in `Vertex::dist` while valid and in `Mris::dist_storage` while
  not (FreeSurfer points the first at the second): `dist`'s module.
- Floating-point operations that can make or meet NaNs use fs.core's `sse` helpers in the official
  build's operand order (the same bits on every platform).
- FS-113: after a negative scale larmorx swaps the box's ends (`reproduce` leaves them reversed).
- FS-115: restoring the target or layer-IV positions of a spherical patch sets its canonical
  coordinates from the restored set (`reproduce`: the temporary set, as FreeSurfer).
- FS-116: reading a deferred face's original area computes it (`reproduce`: FreeSurfer's `NYI`
  message and its deliberate crash, exit status 139).
- `mrisurf_deferSetFaceNorms`'s choice of a parallel loop (`FREESURFER_deferSetFaceNorms_parallel`)
  and `recomputeOrUndeferFaceNorms`'s OpenMP loop are one serial loop each (the same bytes).
- FS-111 (an inflated name of 1,022 bytes or more is taken whole; `reproduce`: the official
  build's abort message and exit status 134) and FS-112 (a command line past 1,000 is dropped in
  both modes, the original's count becoming a memory address) (`docs/findings/freesurfer-surfio.md` §7).
- FS-357 to FS-362 (relay 16, `MRISread`): a ripped vertex among a vertex's known neighbours ends
  that ring where it was filled (`reproduce`: the caller's list read as the previous vertex left
  it, entries past a reallocated list as 0); the old neighbour search's writes past 1,024 entries
  are an error (`reproduce`: the list grows); the old quadrangle format's face lists are rebuilt
  from the faces (`reproduce`: the file's lists, zeros past them, a face number outside the faces
  ending as a segmentation fault, status 139); a face list written past its end after a wrapped
  count grows; the icosahedron reader's lists grow past FreeSurfer's allocation in both modes, a
  vertex of more than 255 faces and the file's numbers outside its counts are refused
  (`reproduce`: the count wraps, an out-of-range write is skipped, a face vertex beyond the room
  ends with status 139). The memory-dependent cases are counted, not compared, by the probe
  (`docs/findings/freesurfer-surfio.md` §18).
