# FreeSurfer 8.2.0: the data files

**Closed to FreeSurfer clean-room implementers.** Written from FreeSurfer's source, its installed
package and runs of its programs by a replica-side agent (`docs/porting-guide.md` §1). A
clean-room implementer of any FreeSurfer program must not open, search or list this file or
`data-files.toml`; what a clean room needs from it comes through its spec.

This is sub-task 4 of FreeSurfer's preparation and the list the plan's data rule 4 asks for
([the FreeSurfer plan](../freesurfer-plan.md), "Data files"): every file of FreeSurfer's package
that a program on a default path reads at run time, with its size, SHA-256, licence and origin, the
programs that need it, where FreeSurfer serves it, and the home the plan's rules 1 to 3 give it.
The machine-readable table is [data-files.toml](data-files.toml) (one `[[file]]` per file,
generated by `validation/investigations/freesurfer-inventory/data_files.py`; never edited by hand).
"Default path" is programs.md's: `recon-all -all` in its two streams (v8, the default, and
`-no-v8`, here "classic"), and the FreeSurfer programs fMRIPrep 25.2.6 and sMRIPrep 0.19.2 run
outside it. Paths are relative to `FREESURFER_HOME`; sizes are in bytes.

## 1. How the list was made

**Measured, not only read.** `data_trace.py` ran 104 jobs, one at a time, each in a 12 GiB memory
box with 4 threads (the reference runs' count), under `strace -f` (every `open`, `openat`, `execve`
and process creation):

- 80 recorded steps: 71 of `ds000005-sub-01-v8` (one per program and argument shape, the left
  hemisphere where both run) and 9 of `ds000005-sub-01-classic` (the classic stream's own
  programs; its later stages run the v8 stream's surface programs with the same data arguments,
  programs.md §3). Each started from the subject directory the recording kept for that step (its
  `before` map, rebuilt from the recording's blobs, `fsaverage` linked as recon-all links it);
- the steps recon-all runs without `fs_time`: `csvprint`, `mri_mcadura_seg`, `mri_vsinus_seg`
  (with `--force`: in the rebuilt directory it found its outputs up to date and stopped),
  `mri_mask` with SynthStrip's mask, `mri_entowm_seg`, and the classic stream's `lta_convert` to
  `mni305.cor.mgz`; the commands are those of the recording's `recon-all.log`;
- the classic stream's two Talairach retries (`talairach_avi --atlas
  3T18yoSchwartzReactN32_as_orig`, then MINC's `talairach`/`mritotal`), which run only when
  `talairach_afd` or Avi's check fails;
- recon-all's own set-up, twice (`recon-all -s <subj> -avgcurv`, v8 and `-no-v8`: the
  configuration, the version listing of 64 programs, one cheap stage);
- `mri_synthseg` once more on a 96³ crop (`--crop 96`), so that it ends inside the box (recon-all's
  call peaks at 21 GiB) and the files it reads after the prediction are seen too;
- fMRIPrep's and sMRIPrep's 13 calls outside recon-all (programs.md §5): `mri_robust_template`
  with two images, `lta_convert`, `mris_expand`, `mri_robust_register`, `mri_coreg`, `bbregister`
  (`--init-coreg`, with its `mri_coreg`, `mri_segreg`, `tkregister2_cmdl` and `mri_surf2surf`),
  `mri_vol2vol`, `mris_convert` (surface and data), `mri_vol2surf` onto `fsaverage`,
  `fsaverage5`, `fsaverage6` and the subject itself.

15 jobs were stopped by their time limit or by the box (`mri_synthseg`, `mri_synthmorph`'s
deformable step inside `fs-synthmorph-reg`, `mri_em_register` twice, `mris_sphere` twice,
`mris_fix_topology`, `mris_place_surface` three times, `rca-surfreg`, `mris_volmask`,
`mri_ca_register`, `mri_ca_label`, `mris_expand`): each had opened its data files before (they are
read at the start), and two more sources cover what a stopped job could have missed:

- every command line of the ten recordings (all steps recorded so far, both streams): a package
  path or a `$SUBJECTS_DIR/fsaverage` path on a command line counts as read by that program;
- the right hemisphere: the jobs ran the left one, and recon-all runs each per-hemisphere stage
  for both with the same arguments, so each `lh.` file read stands for its `rh.` twin.

**What is not counted:** the package's code (`bin/`, `lib/`, any other `bin/`, the Python
modules and scripts, MINC's Perl modules), the Python packages' own files (matplotlib's styles,
certifi's certificates), the system's files and the subject's own files. Nothing wrote into the
package. **Configuration** read at run time is listed (kind "configuration": `build-stamp.txt`,
`sources.csh`, `etc/recon-config.yaml`, `etc/global-expert-options.v8.txt`) because the recon-all
port reproduces what it decides; it is not data to ship. The **licence file** (`FS_LICENSE`) was
read by 55 of the 101 programs seen (not by the Python network programs, nor `lta_convert`,
`mri_info` or `tkregister2_cmdl`); it is the user's own key, never shipped (CLAUDE.md, "Settled
technical choices").

Sizes and SHA-256 are the unpacked package's (`data_refs.py package`, relay 3); the git-annex keys
come from the tag's links (GitHub's `v8.2.0` archive keeps each annexed file as a link named by its
key). Licence and origin per file are `data_files.py`'s `RULES`, each from the file's own notice,
the folder's `COPYING` or readme, or FreeSurfer's licence (third-party.md §2), with the papers the
files come from.

## 4. Where FreeSurfer serves each file

- **The package.** Every file is inside FreeSurfer's 8.2.0 packages
  (`https://surfer.nmr.mgh.harvard.edu/pub/dist/freesurfer/8.2.0/`: the Ubuntu 22.04 `.deb`
  9,618,180,718 bytes, the others 8.3 to 10 GB). The reference package's SHA-256 is in the TOML.
- **FreeSurfer's git repository at the tag** (GitHub, `freesurfer/freesurfer`, tag `v8.2.0`):
  23 files are ordinary files there (the colour tables, SynthSeg's label lists, the three
  sclimbic-family models of 3.3 MB each with their colour tables, the `.ifh` headers of the 4dfp
  atlases, the configuration), each at
  `https://raw.githubusercontent.com/freesurfer/freesurfer/v8.2.0/<tag path>`, a stable address
  pinned by the tag (checked: HTTP 200, and the tag's file has the package file's SHA-256).
- **FreeSurfer's git-annex remote.** The large files are git-annex objects. The tag keeps each as a
  link named by its key, `SHA256E-s<size>--<sha256><extension>` (or the older
  `SHA256-s<size>--<sha256>`), so **the checksum of every annexed file is known without
  downloading it, and it is the package file's own SHA-256** (each annexed file of the list was
  found by its SHA-256). The remote is a public bare repository,
  `https://surfer.nmr.mgh.harvard.edu/pub/dist/freesurfer/repo/annex.git` (annex version 8), and
  an object's address follows from its key: `annex/objects/<md5(key)[0:3]>/<md5(key)[3:6]>/<key>/<key>`
  (git-annex's hash directories; FreeSurfer's README for SynthStrip and SynthMorph tells developers
  to `git fetch datasrc` and `git annex get`). HEAD requests (nothing downloaded) answered 200
  for **every annexed file of the list** (32 objects, 4,148,046,098 bytes, from
  `synthmorph.deform.3.h5` to the 379-byte `TalairachingMean.adf`) and for the four tarballs
  (`fsaverage`, `fsaverage5`, `fsaverage6` and the ICBM 2009c folder's). **The server
  limits how fast a client may ask**: about 100 requests in a minute brought HTTP 429 and then
  refused connections for about an hour, and later requests 20 seconds apart got 429 again after
  nine; HTTP 403 answers came only inside such bursts. A first-use fetcher must therefore ask
  slowly, one file at a time, back off on 429, and verify each file by the SHA-256 in its key.
  Whether FreeSurfer intends the annex remote as a public download address for users is not
  stated anywhere we found (a question below).
- **Tarballs.** `fsaverage`, `fsaverage5`, `fsaverage6` and the ICBM 2009c folder are unpacked at
  build time from one annexed tarball each (`distribution/average/CMakeLists.txt`,
  `install_tarball`: `fsaverage.tar.gz` 320,193,429 bytes, `fsaverage5.tar.gz` 72,198,617,
  `fsaverage6.tar.gz` 86,292,417, `mni_icbm152_nlin_asym_09c.tar.gz` 514,649,342): their files
  are served only inside those, except where the same
  bytes are also annexed on their own: `fsaverage`'s `lh.sphere.reg` and `rh.sphere.reg` are the
  same file as `distribution/average/surf/rh.sphere.reg`, and `fsaverage5`'s and `fsaverage6`'s
  spheres are `distribution/average/surf/lh.sphere.ico5.reg` and `lh.sphere.ico6.reg` (one file
  for both hemispheres each).
- **Only inside the package** (9 files): `build-stamp.txt` (written by the build) and MINC's `mritotal`
  models and settings (`mni/share/mni_autoreg/`, `mni/etc/mni_autoreg/`, on the classic stream's
  second Talairach retry only), which come from MNI's own MINC distribution (`license.minc.txt`)
  and can be fetched from MNI instead.
- **Not used:** `pub/dist/freesurfer/atlases/` holds only the 2011 GCA and 2009 GCS releases, not
  8.2.0's. The SynthStrip and SynthMorph container images on Docker Hub carry their weights too
  (not checked whether the same bytes).
- **Post-release updates of 8.2.0.** `pub/dist/freesurfer/8.2.0/fs820_updates.sh` (2026-03-24)
  fetches `pub/dist/freesurfer/.fs820_updates/<name in "default">` and, file by file after an MD5
  check and a question to the user, replaces installed files. Six archives exist (2026-03-24 to
  2026-06-25; `default` names the newest, `patch_data_20260625.tgz`, 22 MB, not downloaded). The
  first (`patch_data_20260324.tgz`, 5.8 MB, read) replaces only `bin/recon-all` and
  `bin/rca-surfreg` ("fixed bugs in expert options": `rca-surfreg` gains `--expert`; recon-all's
  `if($XOptsFile)` becomes `if($#XOptsFile)`; the patched recon-all's `FS_RECON_VERSION` line is
  left unconfigured, `'@FS_VERSION@ (@BUILD_STAMP@)'`) and one Ubuntu 24 SAMSEG library: no data
  file. The reference runs use the package as released, without updates. *Relay 5 read the
  newest* (`patch_data_20260625.tgz`, 23,515,931 bytes, the orchestrator's D3): for Ubuntu 22 it
  replaces ten files, no data file; on a default path only `recon-all` (the same one-line fix) and
  `rca-surfreg`, which change no run without `-expert` (variation.md §4).

## 5. Licences and origins

- **FreeSurfer's licence covers nearly all of them.** 125 of the 143 files are MGH's (atlases,
  colour tables, `fsaverage` with its labels, the networks' weights, the priors and tables): the
  agreement covers "any software and/or data from FreeSurfer", and its Part B allows
  redistribution with Part B included, the notices kept, research use only (B.4) and no use of
  MGH's names (third-party.md §2). Rule 2 therefore allows them in `larmorx-freesurfer`.
  None of these files carries a licence of its own; their origins are the papers in the table

  cytoarchitectonic maps behind `*_exvivo`, Rosenke et al.'s ventral visual areas); FreeSurfer
  distributes the trained atlases under its own terms, and no other terms are stated with them.
- **MNI's notice:** the MINC models (8 files, conditional) are MNI's (`license.minc.txt`:
  use, copy, modify and distribute for any purpose without fee, the notice in all copies: rule 1's
  "MNI's permissive notice"). `mni305.cor.mgz` and `mni305.cor.stripped.mgz` are FreeSurfer's
  conversion of MNI's `average_305.mnc` (`average/mni305.cor.readme`), and the ICBM 2009c
  registration targets are FreeSurfer's derivation (masked, symmetrised, cropped by its

  FreeSurfer's for MGH's work on it (a question below). None is the same file as MNI's own

- **Washington University's 4dfp atlases** (6 files, 201,328,254 bytes; classic stream only:
  `711-2C_as_mni_average_305`, `711-2B_as_mni_average_305_mask`, and on the first retry

  records name A. Snyder's resampling, 2007 and 2009); the 4dfp code's notice forbids copying
  without written permission (TP-09). Rule 2: fetched from FreeSurfer on first use, as the settled
  choice for the Talairach step already says (CLAUDE.md, decision log 2026-10-19).

## 8. Findings and questions

**Findings** (for the plan and the porting cards):

1. `mri_watershed` (classic stream) reads `average/rigidly_aligned_brain_template.tif` by default,
   a file no command line names (measured; the plan's list did not have it).
2. `talairach_afd` reads `fsafd/Talairaching{Mean,Covariance,Probas}.adf`; recon-all itself reads
   `etc/recon-config.yaml` (through `rca-config`), `etc/global-expert-options.v8.txt` (through
   `fsr-getxopts`) and `build-stamp.txt`, and every tcsh script sources `sources.csh`.
3. `recon-all -s <subj> -avgcurv` in the v8 stream also ran `mri_mcadura_seg` and
   `mri_entowm_seg` (measured in the set-up job): those v8 steps are not gated by the step flags
   the way the classic ones are (for wave 3.6 and programs.md §1; to read in the script).
4. `fsaverage`'s two `sphere.reg` files are one file, and `fsaverage5`'s and `fsaverage6`'s are
   also annexed on their own as `average/surf/lh.sphere.ico5.reg` and `lh.sphere.ico6.reg`.
5. The annexed files' git-annex keys carry their SHA-256: a fetcher has a stable checksum for
   every large file without any download, and the package's files match it.
6. FreeSurfer 8.2.0 has post-release updates (§4); the first changes only expert-option handling.
7. The Python network programs and `lta_convert`, `mri_info`, `tkregister2_cmdl` do not read the
   licence file; 55 of the 101 programs seen do.

**Questions for the orchestrator** (rules 1 to 4 leave them open):

- D1. FreeSurfer's annex remote as the fetch address: it serves the objects publicly and their
  checksums are in the keys, but FreeSurfer documents it for developers, and its rate limit is
  strict. Use it (slowly, verified), or ask FreeSurfer, or fetch from the package (9 GB) only?
- D2. The MNI-derived templates (`mni305.cor*.mgz`, the ICBM 2009c registration targets): treat
  them as MNI's (rule 1: the main package or fetched) or as FreeSurfer's derivation (rule 2)?
  They are small (12,374,295 bytes for the four).
- D3. The newest 8.2.0 update archive (22 MB): download it to list what it replaces (the rule
  "newest upstream versions" may make the updated files the reference), or keep the package as
  released for the reference runs? *Decided* (the orchestrator, 2026-11-12): download it and record
  what it replaces, the reference runs stay unpatched; done by relay 5 (variation.md §4).
- D4. The size limit for shipping small FreeSurfer files in `larmorx-freesurfer`: the TOML uses
  2,000,000 bytes; the folding atlases are 2.86 MB each, the `fsaverage` labels 9.4 MB together.
