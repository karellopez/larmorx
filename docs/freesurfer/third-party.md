**Closed to FreeSurfer clean-room implementers** (written from FreeSurfer's source; see
[README.md](README.md)).

Sub-task 3 of the preparation (CLAUDE.md rule 3: "Audit each ported file for third-party code

and explains; it decides nothing the rules leave open: the questions are in §7 and in the part's

## 1. What was read, and the porting classes

function that the call graph's full view reaches from such a program (what the official binaries
contain; [code.md](code.md) §2), the sources of their CMake targets (the 4dfp tools' Fortran

Burkardt, Thévenaz, Unser, Singleton, GSL, neurite), its licence family and its porting class.
Relay 3 read every flagged place, every bundled package's terms in full
(`distribution/docs/license.*.txt`, the packages' `LICENSE` files and their files' headers) and
the files without a notice (§6).

## 2. FreeSurfer's own licence and its scope

`LICENSE.txt` (FreeSurfer Software License Agreement, version 1.0, February 2011) has three parts:

  reproduce, make derivative works of and distribute the contribution (A.4), and warrants it
  "does not contain any code that requires or prescribes an 'open source license' for derivative
  works", the GPL named as the example (A.6); contributors keep the attributions and licences of
  any third-party code they include (A.2(iii)).
- **Part B** (downloads, the terms LARMORX receives): a royalty-free, non-exclusive licence "with
  respect to MGH's rights in the software" to use, reproduce, make derivative works of, display
  and distribute it, provided that (a) the terms are accepted; (b) every copy or sublicence,
  source and executable and user documentation, carries all of Part B, prefaced by the words "All
  or portions of this licensed product (such portions are the "Software") have been obtained
  under license from The General Hospital Corporation "MGH" and are subject to the following terms
  and conditions:"; (c) attributions, copyright notices and licences are kept; (d) modified
  versions are clearly marked and not presented as the original; (e) one considers, without
  obligation, publishing the source of modifications. B.2 allows proprietary programs and
  different terms for sublicences of modifications; **B.3 grants no rights in third-party
  software**; B.4 research use only, no clinical use; B.6 no use of MGH's names for promotion;
  B.7 rights end on breach. Part C: Massachusetts law. If one distributes software downloaded from

**Scope (the first pass's question 1).** The agreement covers "downloading, copying, modifying,
displaying, distributing or use of any software and/or data from FreeSurfer"; Part B licenses MGH's
rights in it. A file without a notice is therefore under Part B as far as MGH holds the rights
(its own staff's work, or a contribution licensed to MGH by Part A), and third-party code inside it
is not (B.3): what each such file holds decides. §6 lists them by name with what they hold. One
outside view, for the record: dcm2niix's author writes in FreeSurfer's own copy "FreeeSurfer does
not use a permissive license, so we must reverse engineer code"
(`packages/dcm2niix/nii_dicom_batch.cpp` 4487).

## 4. The findings inside the files

Each finding: where it is, what the code is and the evidence, the terms, when it runs, and what it
means for porting. `third-party.toml` lists the programs reaching each (core view).

**TP-01. `OpenRan1` is VXL's `vnl_random`, not Numerical Recipes' `ran1`** (the first pass's
question 3). `utils/numerics.cpp` 1256-1281: a static `vnl_random` reseeded whenever the seed
changes, returning `(float) drand64(0.0, 1.0)`; "meant to mimic ... ran1" describes the calling
convention only (a seed by pointer). `setRandomSeed` (`utils/utils.cpp` 77-101) seeds `srand`,
`srandom` and `OpenRan1` (a second call with the same seed first draws once with seed − 1, DNG's
2014 change, so the generator restarts) and draws one number; `randomNumber` (106-153) takes the
seed from `FREESURFER_SEED` when none was set, else a time-based negative seed with the message
"... supposed to be reproducible but seed not set". `vnl_random` is Marsaglia and Zaman's
subtract-with-borrow on 37 words seeded by the LCG `x·1664525 + 1 mod 2³²` with 1000 warm-up draws;
`drand64` = `lrand32()/0xffffffff + lrand32()/0xffffffff²`, scaled. **The code is identical in
ITK 4.13.2 (the official build's, TP-11) and ITK 5.4.5** (LARMORX's pinned ITK) apart from the
default constructor's initialisation moved into the header (no change in values: compared after
removing comments and spacing, §8). Terms: BSD-3-Clause (VXL). Portable with VXL's notice; LARMORX
already ports VNL routines under that notice (`crates/larmorx-core`'s `vnl_svd`, `vnl_eigen`,
`vnl_qr`). Two points for the exact replica of every `-seed` (and sub-task 5): `OpenRan1` exits
when called from an OpenMP thread other than 0, so its sequence does not depend on threads; the
order of the two `lrand32()` calls inside `drand64` is unspecified in C++ (the operands of `+`),
so the official binary's order must be measured, and `drand64` can exceed 1 by up to 2⁻³² (then
`(float)` rounds to 1).

**TP-02. The `Open*` wrappers call VNL.** `OpenSvdcmp` (`vnl_svd<float>`), `OpenLUMatrixInverse`,
`OpenMatrixDeterminant`, `OpenEigenSystem` (`vnl_symmetric_eigensystem`),
`OpenNonSymmetricEigenSystem` (`vnl_real_eigensystem`), `OpenQRdecomposition` (`vnl_qr`),
`OpenDFPMin` (`fs_lbfgs`), `OpenPowell`/`OpenPowell2` (`fs_powell`), `sc_linalg_cholesky_decomp`
(`vnl_cholesky`). The header says it: "Wrappers for core math routines from open-sources: VNL and
CEPHES" (Dennis Jen and Silvester Czanner). Terms BSD-3-Clause (VXL), with netlib's LINPACK and
EISPACK through `v3p`. Portable with notice; each VNL routine used must be checked between ITK
4.13.2 and 5.4.5 before LARMORX's 5.4.5 ports are reused (TP-11).

**TP-03. The "GSL library replacement" is a transcription of GSL** (`utils/numerics.cpp`
1856-2230; "Author: Silvester Czanner, Created 7/26/2006, Description: GSL library replacement for
Freesurfer"). `sc_inc_status`, `sc_rng_get` and `sc_rng_set` follow GSL's `rng/ranlux.c`
(`increment_state`, `ranlux_get`, `ranlux_set_lux`) statement by statement: the same masks and
`two24` constant, the same `i == 0 ? 23 : i − 1` steps, the default seed 314159265, F. James's
seeding (`k = seed / 53668; seed = 40014·(seed − k·53668) − k·12211`, `+ 2147483563`),
`i = 23, j = 9, skip = luxury − 24` with luxury 389 ("only one type of rng is supported at this
moment (ranlux389)", `utils/randomfields.cpp` 79), and the carry from `u[23]`. `sc_gamma_int`,
`sc_gamma_large`, `sc_gamma_frac`, `sc_ran_gamma`, `sc_ran_fdist`, `sc_ran_chisq`, `sc_ran_tdist`,
`sc_ran_flat` follow GSL 1.8's `randist/gamma.c`, `fdist.c`, `chisq.c`, `tdist.c`, `flat.c`
expression by expression (GSL 1.8 was the release of 2006); `sc_ran_gaussian` and
`sc_ran_exponential` follow GSL's polar method and `-mu·log(u)` with `sc_uni` where GSL 1.8 has
`uniform_pos`. GSL is GPL-2.0-or-later (1.8's headers; GPL-3.0-or-later in later releases); the
file carries FreeSurfer's notice only (and Part A.6's warranty says contributions hold no GPL
code). The algorithms themselves are published: M. Lüscher, Comput. Phys. Commun. 79 (1994)
100-110; F. James, ibid. 111-114 (the seeding); Knuth, TAOCP vol. 2 (Ahrens's gamma method,
exercise 16); Marsaglia's polar method; Marsaglia (1980) for the t distribution. **Runs:**
`mri_coreg` by default (coordinate and intensity dithering are on, seed 53, `mri_coreg.cpp`
207-208, 227, 419-444): fMRIPrep's `bbregister --init-coreg` runs it; `mris_expand` only with a
random thickness map. Porting: a question (§7, Q2).

**TP-04. `mri_normalize`'s cubic spline is John Burkardt's spline library.**
`SplineCubicSet`, `SplineCubicValue`, `d3_np_fs` (`utils/numerics.cpp` 1417-1680 with their
comment blocks, behind `OpenSpline` and `OpenSplint` at 1287 and 1305): "Original Author: John Burkardt,
http://www.csit.fsu.edu/~burkardt/cpp_src/spline/spline.html", his comments kept. Burkardt's page
says today "distributed under the MIT license" (read 2026-11-12, §8); the terms of the version
FreeSurfer copied (the csit.fsu.edu address, about 2006) are not recorded in FreeSurfer. Burkardt's
probability routines in the same file (`OpenBetaIncomplete`, `OpenGammaIncomplete`, with
Applied Statistics AS63 and AS239) are reached by no default-path program. **Runs:** every
`mri_normalize` (MRInormalize calls `MRIsplineNormalize` unconditionally, `utils/mrinorm.cpp`
749): T1.mgz and brain normalisation on both streams. The maths is a textbook cubic spline with
first-derivative ends and a tridiagonal solve; porting: a question (§7, Q3).

**TP-05. `mriBSpline.cpp` follows EPFL's B-spline code.** Martin Reuter's file: "This Code is
based on: P. Thevenaz, T. Blu, M. Unser, Interpolation Revisited, IEEE TMI 19 (2000) 739-758 and
code (for 2D images) obtained from http://bigwww.epfl.ch/thevenaz/interpolation/ and
http://bigwww.epfl.ch/sage/pyramids/"; the routine names (`ConvertToInterpolationCoefficients`,
`InitialCausalCoefficient`, `InitialAntiCausalCoefficient`) are those of EPFL's `coeff.c`, and the
pyramid filters carry "Author: Michael Unser, NIH, BEIP, May 1992". EPFL's `coeff.c` (dated
January 5, 2009) states no licence; the page states none either (both read 2026-11-12); EPFL's
disclaimer page no longer answers. FreeSurfer's file carries MGH's notice. **Runs:**
`mri_robust_template`'s final resampling (cubic B-spline by default, `mri_robust_template.cpp`
134) when sMRIPrep or recon-all average several T1w images; the robust tools' pyramid for large
images (`Registration.cpp` 3016); `mri_convert` and `mri_vol2vol` only with cubic interpolation
(no default-path command asks for it, programs.md). The method is the published recursive
filtering that ITK's `BSplineDecompositionImageFilter` and SciPy's `spline_filter` also implement
(LARMORX ports both). Porting: a question (§7, Q4).

**TP-06. Numerical Recipes' `nrutil` allocators.** `vector`, `matrix`, `free_vector`,

reached names against NR's index, §8).
