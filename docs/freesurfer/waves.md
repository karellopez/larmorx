# FreeSurfer 8.2.0: the waves and the layout

**Closed to FreeSurfer clean-room implementers.** Written from FreeSurfer's source (its call
graph, `code.md`) by a replica-side agent (`docs/porting-guide.md` §1). What a clean-room
implementer needs of it (a crate's name, an item's number) comes through its brief.

Sub-task 6 of FreeSurfer's preparation (relay 6): the waves of [the plan](../freesurfer-plan.md)
checked against the inventory and put in the user's order, the dependency map, and the crates of
`crates-freesurfer/` and of the clean rooms. The order of work is [queue.md](queue.md); one
porting card per program is in `cards/`. The tables between `<!-- waves.py: ... -->` markers are
generated by `validation/investigations/freesurfer-inventory/waves.py` (§7), with its
machine-readable output [waves.toml](waves.toml); the prose is written by hand.

## 1. The order, and what it changes in the plan

**The user's order** (2026-11-12, decision log "FreeSurfer's borrowed pieces and its two
streams"): the programs both streams share first, then the classic-only ones, with the v8-only
networks as a parallel track. So:

| Wave | What | Change |
|---|---|---|
| 3.1 Foundations | the formats, the image and surface structures, FreeSurfer's maths, random numbers and messages; plus x87 80-bit arithmetic, the clean-room pieces the placement table asks for, the VNL routines and C-library behaviours the replicas need, a unit oracle | grown (§3) |
| 3.2 Volumes | the volume programs both streams run, and fMRIPrep's volume and registration programs | corrected |
| 3.3 Atlas | the GCA programs both streams run | corrected |
| 3.4 First surfaces | tessellation to the fixed, remeshed surface | corrected |

| **3.6 The classic-only programs** | `mri_watershed`, the Talairach chain, `talairach_afd`, `mri_ca_label` | **new** |
| **N The v8 networks** | the inference core, the four network programs, their scripts and what only those scripts run | **new: a parallel track** |
| **3.7 `recon-all`** | the script and its helpers | **was 3.6** |

**fMRIPrep's programs outside `recon-all`** (`mri_coreg`, `mri_robust_register`,
`mri_robust_template`, `bbregister` with `mri_segreg` and `tkregister2_cmdl`, `mri_vol2surf`,
`mris_convert`, `mris_expand`, `mri_surf2surf`, `mri_vol2vol`) belong to no stream: they come with

**The plan's wave table, corrected** (from programs.md's measured stages, relays 1 and 2; the
reasons per program are in §2's notes):

  N). `mri_nu_correct.mni`'s N3 (`nu_correct`) goes to *later* (only with `-no-ants-n4`).

- **3.4:** adds `mris_topo_fixer` (when `mris_fix_topology` leaves a defect), `mris_remesh` (on
  by default), `mris_defects_pointset` and `mri_label2label` (from 3.5: `defect2seg`, stage 52,

- **3.5:** adds `mris_curvature_stats`, `mris_label2annot`, the scripts `label-cortex` (with its v8
  helpers `mri_cor2label`, `fscalc`, `mri_mergelabels`), `vertexvol`, `rca-surfreg` and
  `fsr-getxopts`, `bbregister`'s `mri_segreg` and `tkregister2_cmdl` (CorTechs' terms: the clean

- **N:** the four network programs (`mri_sclimbic_seg` added, three models), their scripts,
  `csvprint` (SynthSeg's volumes), and `mri_concatenate_lta`, `mri_warp_convert`, `mri_diff`,
  `mri_compute_seg_overlap` (only the v8 scripts run them).
- **later:** `nu_correct` (MNI's N3), MINC's `talairach` (the fallback after two failed Talairach
  checks), MARS (P-13).

## 3. The dependency map

**How it is computed.** Every file the 72 compiled default-path programs reach (code.md's core
view) belongs to one module (the table below); every module has the wave that brings it. Each
reached function goes to one queue item: the program's own item when one program alone reaches it
and that program's wave is not earlier than the module's; otherwise the module's item. A program
of an earlier wave that reaches a later module's functions has option paths that **wait** for that
module; they are completed in that wave ("the option paths ..." items of the queue). So every
line of FreeSurfer's source is counted once, in the item that brings it.

**A static superset.** The call graph follows every call a program's code can make, not what a
run executes: `mri_add_xform_to_header` "reaches" 6,014 lines of the GCA code because `MRIread`
can read a `.m3z` morph as a volume; on recon-all's call it runs none of them. The sizes below are
upper bounds for full completeness (every option of every program, which the user's rule asks
for), not the default paths' cost. The unit oracle (queue item 3.1-02) could measure the default
paths exactly (a coverage build replaying each recorded step): a proposal (§6, W6).

**Outside the graph.** The call graph covers FreeSurfer's tree: the statically linked ITK 4.13.2
and VNL code (N4's filters, the denoiser's, `vnl_svd`, `vnl_random`, ...) and the Python of the
network programs are not in its lines. They come through the permissive items (3.1's VNL and

are given in their rows.

**Why 3.1 grew.** FreeSurfer's library is one block (`libutils`): every compiled program links
it, and its volume reader alone reaches the DICOM probe, GIFTI through expat, MINC's `.xfm` reader
and the surface structure. With the rule above, 3.1 takes the volume side of the library (the
formats, the `MRI` structure, transforms, labels, colour tables, the filters) and the surface
structure with its I/O (reading a surface computes its metric properties); the GCA code waits for
3.3 and the rest of the surface library for 3.4.

## 4. The crates

Three kinds of code, kept apart by licence (CLAUDE.md rule 1; the placement table,
third-party.md §9).

**The replicas: the workspace `crates-freesurfer/`** (FreeSurfer's licence, the wheel and program
`larmorx-freesurfer`; CLAUDE.md rule 3). It builds the Apache crates by path, never `crates-gpl/`
or `crates-nc/`. Library crates in layers, each depending only on the ones above it:

| Crate | Modules | Depends on |
|---|---|---|
| `larmorx-freesurfer-core` | `fs.core` (messages, diagnostics, environment, version stamps, ROMP), `fs.maths` (matrices, numerics wrappers, `fs_powell`, `fs_lbfgs`, statistics) | `larmorx-core` |
| `larmorx-freesurfer-io` | `fs.io` (MRIread/MRIwrite, tags, the format probe), `fs.labels` (colour tables, annotations, labels, `register.dat`, point sets) | core, `larmorx-io` |
| `larmorx-freesurfer-volume` | `fs.volume` (the `MRI` structure, transforms, resampling, warp fields, CMA), `fs.bspline` (EPFL's B-splines) | core, io |
| `larmorx-freesurfer-filter` | `fs.filter` (filters, normalisation, segmentation helpers, flood fill) | volume |
| `larmorx-freesurfer-surf` | `fs.surfio` (the surface structure and its I/O), `fs.surf` (the rest of the surface library), `fs.mars` (later) | volume |
| `larmorx-freesurfer-deform` | `fs.deform` (surface deformation) | surf |
| `larmorx-freesurfer-defect` | `fs.defect` (the topology fixer's defects) | deform |
| `larmorx-freesurfer-gca` | `fs.gca` (GCA, GCA morphs, MRI morphs) | filter, surf |
| `larmorx-freesurfer-robust` | `fs.robust` (Reuter's robust registration) | volume |

and the programs, one crate per wave, one module per program inside it:
`larmorx-freesurfer-volumes` (3.2), `-atlas` (3.3, and 3.6's `mri_ca_label`), `-topology` (3.4),
`-cortex` (3.5), `-classic` (3.6), `-networks` (N), `-recon` (3.7: `recon-all` and its helpers,
which run the other crates' programs in-process), and `larmorx-freesurfer-cli` (the program
`larmorx-freesurfer`, the wheel, the registry, the settings overlay of larmorx's three options).

**The permissive replicas: the main package.** Third-party pieces under permissive terms (P-01 to
P-07, P-15 to P-17) are ported from their own upstream source, not from FreeSurfer's, so they live
in the Apache crates and any agent may write them: `larmorx-core` (x87 80-bit arithmetic,
`vnl_random`, POSIX `drand48`, the missing VNL and netlib routines, nlohmann's number formatting,
the argparse, Geometric Tools' distances, the FNV hash, Cephes' constants), `larmorx-io` (GIFTI
with expat, MINC's `.xfm`, niftilib, the DICOM probe), `larmorx-image` (N4 and the non-local means
denoiser, checked at ITK 4.13.2's arithmetic, third-party.md §10), and a new `larmorx-nn` (the
networks' inference core, P-07). FreeSurfer's own changes to such a piece (the twelve MINC files)
stay in `crates-freesurfer/`.

**The clean rooms: the main package** (Apache-2.0, written from `specs/` and black-box runs only;
each crate added to the clean-room audit's `CLEANROOM_CRATES` and `CLEANROOM_PATHS`, with a
FreeSurfer entry like `FSL_TOOLS`, by the orchestrator in the part that creates it):

| Crate | What |
|---|---|
| `larmorx-fs-core` | messages, maths, the volume structure, filters, the B-spline interpolation (P-10's clean room), the robust registration |
| `larmorx-fs-gca` | GCA atlases and morphs |
| `larmorx-fs-surf` | the surface structure and library, deformation, defects |
| `larmorx-fs-volumes`, `-atlas`, `-topology`, `-cortex`, `-classic`, `-networks`, `-recon` | the programs, as for the replicas; `-cortex` holds `tkregister2_cmdl`'s clean room (P-11), `-classic` the Talairach registration's (P-12, the 4dfp tools: no replica) |
| `larmorx-io` (clean-room files) | FreeSurfer's formats: MGH/MGZ (moved from `larmorx_tedana::formats`, the plan), LTA, `.xfm`, `.m3z`, labels, annotations, colour tables, curvature, surfaces, GCA, `.gcs`, `.tif`; listed like `CORE_FILES` |
| `larmorx-core` (clean-room files) | RANLUX389 and GSL's distributions (P-08, GSL's family: GSL's source joins the restriction table) and the cubic spline (P-09), both used by the replicas too |

**Names.** `larmorx-freesurfer-*` are replicas (FreeSurfer's licence), `larmorx-fs-*` clean rooms
(Apache-2.0). Other names are possible (§6, W2).

**Parallel agents never touch the same files.** One item is one module's files or one program's:
`src/<module>/` or `src/<program>/` in its crate. The pieces of one module come one after the
other (one agent per module at a time); programs of one crate can go side by side. The shared
touch points are one `pub mod` line in a crate's `lib.rs`, its `Cargo.toml`, the registry of
`larmorx-freesurfer-cli` and the golden registry: minimal changes, merged by the orchestrator.
A replica's program and its clean room are always different crates (and different agents).

## 6. Questions (for the orchestrator)

- **W1.** fMRIPrep's programs outside `recon-all` placed with the shared programs (3.2, 3.5), as
  the plan had them: is that the user's order, or do they follow the classic-only ones?
- **W2.** The crate names: `larmorx-freesurfer-*` for the replicas, `larmorx-fs-*` for the clean
  rooms (beside `larmorx-fsl`, `-fs-` may be misread; an alternative is `larmorx-surfer-*`).
- **W3.** The permissive parsers (expat for GIFTI, the DICOM probe, nlohmann's parser): a full
  port of each, or an existing pure-Rust parser where the parsed values are the same by
  construction (only messages on malformed input would differ; full completeness asks for them)?
  The writers (gifticlib's long-double formatting, nlohmann's numbers) need the exact port.
- **W4.** The unit oracle (3.1-02, FreeSurfer's libutils built with GCC 8.4.0): worth a relay?
  It turns the foundations' checks into direct function calls; without it they are checked only
  through the programs' replays.
- **W5.** recon-all renumbered 3.6 → 3.7 (the classic-only programs take 3.6): next-steps and the
  plan say "3.6 `recon-all`".
- **W6.** The sizes are static upper bounds. A coverage build (the unit oracle with `--coverage`,
  each recorded step replayed) would give the default paths' exact functions and let the queue
  bring them first, the rest of each program as completeness items.
