**Design**
- **Inputs:** generated by the tests from a SplitMix64 integer generator, written out in both Python and Rust so the two give identical inputs and nothing depends on numpy's random streams. After that, only `+ - * /` and squares.
  - Images are head-like phantoms, masks and labels on oblique grids (rotation built from 3-4-5 and 5-12-13 triangles).
  - Sizes are 24×20×16, 16×14×12×4 and 32×24.
  - **One exception to the size rule:** AFNI's 3dTshift refuses fewer than 5 time points, so its series is 8×6×5 with 10 volumes (2,400 values).
- **What is hashed:** SHA-256 of each output's data. For files a tool writes, the NIfTI header bytes and the data are hashed separately.
- **Mismatch reporting:** the JSON also keeps 8 sampled values and the exact sum per array. From those the test prints the max absolute and ulp difference at the samples; a mismatch confined to unsampled voxels only shows as a different sum.
  - I did this instead of recomputing a reference in the test, because most functions have no cheap independent reference.
  - The samples make `golden.json` 66 KiB, about half its size.
- **On failure:** CI uploads the mismatching outputs as an artifact (capped at 50 MB). `python scripts/record_golden.py --compare <dir>`, run here, gives the full max-abs and ulp difference.

**Not bit-identical by construction: `lx.transforms`' numpy 4×4 matrices**
- Forcing numpy onto other OpenBLAS kernels here (`OPENBLAS_CORETYPE`):
  - products `inv(A)@M@A` of 10,000 random affines differ in 99.9% of cases between kernels with fused multiply-add (Haswell, Zen) and those without;
  - inverses differ in 23% of cases between the Haswell and Sandy Bridge kernels.
- So fMRIPrep's own last bits depend on the CPU, and macOS numpy uses Accelerate instead.
- My first inputs happened to make those products exact, so I changed them to rotation centres that aren't multiples of a power of two, and added a float64 copy of the resampled series.
- Under a non-FMA kernel, the golden check now fails 2 cases, as intended:
  - `py.transforms.files`: last bits of the loaded matrices;
  - `resample_series`: 81 ulp in the float64 output; the float32 output is unchanged.
- **Decision for you:** `golden.md` lays out the options. I recommend Rust 4×4 arithmetic using fused multiply-add chains in index order. That reproduces OpenBLAS's Haswell/Zen kernel bit for bit (300 of 300 random products), so Linux x86-64 stays identical to fMRIPrep on FMA CPUs. The inverses would also need a port of OpenBLAS's 4×4 `dgesv`. I did not change the resampler's numerics.

**Unverified until CI runs:** whether the gzip bytes from the pure-Rust compressor match across platforms (one I/O case hashes them), and whether AVX-512 OpenBLAS kernels match.

**Library fix found while writing the tests:** `HmcResult.save_mats`, `save_par` and `save_itk` wrote CRLF line endings on Windows (`Path.write_text` translates newlines). They now write LF everywhere, as the CLI does.
