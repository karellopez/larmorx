## Why
The user wants the work faster and cheaper in tokens without losing quality. Most time goes into running the original programs, again and again on the same inputs (the agent's records, the orchestrator's re-runs at every merge, the golden recording's parity smoke tier): one ANTs registration of a real brain takes up to 95 minutes. The original's output for the same program build, inputs, arguments and settings never changes, so it should be computed once.

## Task: the oracle-output cache (decision log 2026-10-23, "speed at the same quality", point 1)
1. **A content-addressed cache of the original programs' runs**, used by every parity suite: the key is a SHA-256 over the oracle's identity (the program binary's SHA-256, and for wrappers the build's; the CORE-MATH preload's when preloaded; fMRIPrep's image digest for its runs), the program and its arguments with every path replaced by the SHA-256 of the file it names (inputs) or its role (outputs), the environment that matters (thread counts, seeds such as `ANTS_RANDOM_SEED`, AFNI and ITK variables, `LD_PRELOAD`), and the inputs' SHA-256s. The value: the exit status, stdout, stderr and every output file, stored under `<workspace>/oracles/cache/` (outside git; configurable by `LARMORX_ORACLE_CACHE`), written atomically, with a small JSON manifest per entry (the key's parts in readable form, the time the run took, the date, the larmorx commit that wrote it).
2. **Only what the original determines is cached.** Runs whose result the original itself varies are never cached and always run fresh, because that variation is what the records measure: runs with a clock-seeded random generator (ANTS-72's construction, Atropos and antsAI with the clock's seed), the multi-thread runs of a thread band unless the program is shown deterministic at that thread count, anything a case marks `nondeterministic`. Make the rule explicit per runner and per case, documented, with a test.
3. **Modes:** `--oracle-cache use` (the default: reuse, run and store on a miss), `refresh` (run, compare with the stored entry, report any difference loudly, then store), `off`; and `python -m larmorx_validation oracle-cache verify --sample N` that re-runs N random cached entries and checks they give the same bytes (a drift detector: a changed oracle changes the key, but this catches anything the key misses). A difference found by `refresh` or `verify` is a finding, never silently overwritten.
4. **The records say it:** each record's header names how many original runs came from the cache and how many ran, and the cache's location; nothing else in a record changes (a record made from the cache must be byte-identical, apart from those lines and the timings, to one made without it: prove it on the smoke tier and on a standard suite of each family).
5. **No duplicate runs (point 2):** `scripts/record_golden.py` reuses a passing parity smoke tier of the same clean commit (a marker the smoke run writes: commit, time, result) instead of running it again; `scripts/orchestration/verify-merge.sh` and the README use the cache.
6. **Measure the gain:** the smoke tier and one standard suite per family (ANTs registration, an ANTs program, AFNI, head motion), cold and warm, before and after: wall time and the number of original runs, in the report and in a short section of `docs/validation/README.md` (through the handoff) or `docs/benchmarks/`.
