## Task 1: differential random testing (`python -m larmorx_validation difftest`)
1. **A harness** (`validation/src/larmorx_validation/difftest/`): per tool a small descriptor (option grammar with valid ranges and combinations, input generators, how to compare, which implementations), so adding a tool (FSL's mcflirt and BET are about to be merged) is a short file. Inputs come from seeded random numbers and plain arithmetic (no transcendental functions; the golden rule), small (at most 32³, 4 to 8 volumes for 4D) but varied: sizes (odd, 1-voxel-thick, anisotropic), orientations (qform/sform codes, obliques, flips), data types and `scl_slope`/`scl_inter`, value ranges (constant, zeros, negative, huge, tiny, integer steps), masks, 4D timing (TR, slice timing), plus small real crops from `larmorx-testdata` where a tool needs anatomy. Every run is reproducible from (tool, seed, case number).
2. **Every finished tool,** through the same runners and comparators as its parity suite: NIfTI I/O, ITK transform files and HDF5, antsApplyTransforms, ImageMath (every operation fMRIPrep, sMRIPrep and sdcflows call, then the rest), ThresholdImage, MultiplyImages, SmoothImage, ResampleImage(BySpacing), N4BiasFieldCorrection, DenoiseImage, antsRegistration (tiny images, few iterations, every stage family), antsAI, antsAffineInitializer, Atropos, 3dTshift, 3dAutomask, 3dUnifize (replica and clean-room original each), head-motion correction (the clean-room original against mcflirt), the BOLD resampler. Replicas: bit-identical (compare in `reproduce` mode; in default mode check that the corrected cases are exactly those a D13 notice names). Clean-room originals: their records' thresholds. Programs that vary (clock seeds, thread bands): fixed seeds and one thread for the comparison; the variation itself stays the parity suites' job.
3. **Shrinking and permanent cases:** a difference is shrunk to the smallest input and fewest options that still show it, saved as a recipe (`validation/difftest/cases/<tool>/<id>.json`: generator, seed, arguments, what differs) that the tool's parity suite loads as a regular case from then on (all tiers that fit; the smoke tier if small).
4. **Triage per the user's rule:** a clear larmorx mistake in a replica: fix it now (bit-identical again, unit test, the permanent case, gates); in a clean-room original: report it with its reproducer. A defect of the original: a register entry (through the handoff, IDs below) decided by rules A-D, with the D13 switch where the rules require it. Unclear: list it for the orchestrator.
5. **The oracle cache:** originals run through `oracle_cache.run`; random runs must not make the cache grow without bound (a policy: e.g. keep entries only for findings and permanent cases, or an LRU/size cap for difftest's namespace; document it); every finding replays exactly.
6. **Nightly operation:** `difftest --tools all --budget <hours> --jobs N --seed <YYYYMMDD>` writes `oracles/difftest/<date>/` (cases run per tool, differences, shrunk reproducers, timings) and a short morning report `report.md`; a `scripts/orchestration/difftest-nightly.sh` (run from cron or by hand; never in CI).
