## The user's decisions (2026-11-11; final, do not re-propose the alternatives)
1. **Command-line options with the Python API's names** (the user asked for "an easy way for the majority of users, like specific flags" instead of environment variables for threads, the implementation and the defect mode, keeping the variables; then, after a first proposal of shorter switches: "I prefer mirrored names"):

   `larmorx [--n-threads N] [--implementation auto|replica|clean-room] [--upstream-defects fix|reproduce] <family> <tool> <the original's arguments>`

   (and `lx`, the alias). Each option is the Python argument with dashes (`n_threads`, `implementation`, `upstream_defects`) and takes the same values as Python and as the environment variable; **one spelling each, no shortcuts or aliases**; `--opt value` and `--opt=value` alike. The options sit **between `larmorx` and the family**, so they never clash with the original programs' options; an option after the family belongs to the tool, as today. The environment variables keep working; **an option given wins over its variable**. `--n-threads N` is one option for every family (ANTs reads `NSLOTS`/`ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS` today; AFNI, FSL and `mri hmc` `OMP_NUM_THREADS`; the replica programs `larmorx-nc` and `larmorx-gpl` get theirs through their child process's environment); `0` = every logical CPU; the command line's default stays every logical CPU (Python's stays 1). A tool whose original has its own thread option (tedana's `t2smap --n-threads`, sdcflows' BIDS app `--nprocs`/`--omp-nthreads`): when that option is on the command line it wins, otherwise `--n-threads` applies; `--help` and the docs say so per tool. A wrong value is a clear message with the usage and the non-zero exit status of the program's other usage errors. `larmorx --help` shows the three options, one line each, with the variables they replace.
2. **The value `original` becomes `clean-room`** (the user: "I prefer clean-room instead of original": on the command line and in the docs "the original" means FSL's or AFNI's own program): `implementation="clean-room"` in Python (the `ImplementationName` type, every wrapper's docstring), `--implementation clean-room`, `LARMORX_IMPLEMENTATION=clean-room`, and what a result reports (`Implementation(kind='clean-room', ...)`), the messages that name the value (e.g. "LARMORX_IMPLEMENTATION=original ..."). **`original` stays accepted everywhere** as the old spelling (code written for 0.1.0rc1 keeps working): Python gives a `DeprecationWarning`, the command line and the variable accept it silently; the docs name it once as the old spelling. Internal identifiers (Rust enum variants, file names, records' historical text) need not change; records and golden checksums must not change.
3. **The companion programs** `larmorx-nc` and `larmorx-gpl` accept the same options where they apply: `--n-threads`, `--upstream-defects`; `--implementation` in a replica program: `replica` accepted as a no-op, `clean-room`/`auto` refused with a clear message (or refuse the option altogether: choose, document). **Every future package** (FreeSurfer's `larmorx-freesurfer`, reached as `larmorx freesurfer <program>`) takes the same options from its first tool: the rule's text goes into the handoff for `docs/architecture.md` and `docs/porting-guide.md`.
