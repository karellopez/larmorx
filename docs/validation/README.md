# Validation records

One record per validated tool: larmorx compared, case by case, with the reference implementation it replicates, on the catalog of `larmorx-testdata` (a separate repository next to this one; not published yet). Each record states the thresholds, the environment, every expected divergence with its reason, and the result of every case. They are generated by the [validation package](../../validation/README.md). The same suites run under pytest (`tests/parity`); CI skips them until the test data are published.

**Against a real fMRIPrep run.** [fmriprep-stages](fmriprep-stages.md) runs larmorx's tools,
step by step, on the inputs and parameters fMRIPrep 25.2.6 itself used (read from nipype's
working directory of an oracle run), and compares them with fMRIPrep's own output at each
step; where they differ, the step is re-run in fMRIPrep's image and with the oracle builds to
separate thread effects, ANTs' version, glibc's maths and larmorx. It is a record of the
pipeline's stages, not of one tool, so it has no status of its own; it also lists the tools
larmorx does not have yet. One record per oracle run:

| Record | Run | What it adds |
|---|---|---|
| [fmriprep-stages](fmriprep-stages.md) | ds000005 sub-01 | three BOLD runs, no field maps, no slice timing |
| [fmriprep-stages-ds005040](fmriprep-stages-ds005040.md) | ds005040 sub-002 | PEPOLAR field map (`topup`) applied with the Jacobian, slice timing: both 3dTshift implementations, PIPE-03 on a real field map |
| [fmriprep-stages-ds005454](fmriprep-stages-ds005454.md) | ds005454 sub-16 | two T1w (the pre-template N4), `phasediff` field map, an oblique multiband BOLD of 280 volumes |
| [fmriprep-stages-ds005752](fmriprep-stages-ds005752.md) | ds005752 sub-ON01016 | two BOLD runs with slice timing; its direct `fieldmap` is not used by fMRIPrep (no `IntendedFor`) |

[fmriprep-stages-float](fmriprep-stages-float.md) re-ran the antsApplyTransforms stages of
ds000005 (A06, A11, F08, F09, F12) after larmorx learnt `--float 1` (2026-10-11); the
regenerated [fmriprep-stages](fmriprep-stages.md) now covers them, so it is kept as history.
PIPE-03's effect on fMRIPrep's own field maps is collected in
[resample-series-jacobian](resample-series-jacobian.md).

These records compare larmorx with the original tools on Linux x86-64. That the other five
platforms reproduce larmorx's own Linux x86-64 output is checked by the golden tests, in CI:
[golden.md](golden.md).

**The ANTs oracle** is ITK 5.4.5 and ANTs 2.6.5 built from the pinned tags by
`scripts/build_ants_oracle.sh` into `<workspace>/oracles/ants-2.6.5`. The records compare
with what the C++ source defines (CLAUDE.md rule 8), so the build must not miscompile it:
GCC 11.4 and 12.3, Ubuntu 22.04's compilers, drop float roundings at `-O3` (GCC bug 110182,
[ants-n4 findings](../findings/ants-n4.md)), and the script stops when its compiler probe
finds that. The oracle in use is built by conda-forge's GCC 14.3.0, installed in a user-level
environment, with ITK's and ANTs' own flags; `BUILD_INFO.txt` records the compiler, the flags
each build used and the probe's result, and the records quote it. The first oracle, built by
GCC 11.4, is kept as `oracles/ants-2.6.5-gcc11-O3`; `LARMORX_ANTS_BIN=<dir>/bin` points any
ANTs suite at another build.

```bash
conda create -p <workspace>/oracles/toolchains/gcc-14.3 -c conda-forge --override-channels gxx_linux-64=14.3.0 gcc_linux-64=14.3.0
T=<workspace>/oracles/toolchains/gcc-14.3/bin
scripts/build_ants_oracle.sh --jobs 4 --cc $T/x86_64-conda-linux-gnu-gcc --cxx $T/x86_64-conda-linux-gnu-g++ --ldflags "-static-libstdc++ -static-libgcc"
```

Reproduce a record:

```bash
pip install -e ../larmorx-testdata -e "validation[oracles]"
python -m larmorx_validation parity nifti-io --tier standard --out docs/validation
python -m larmorx_validation parity ants-apply-transforms --tier standard --out docs/validation
python -m larmorx_validation parity afni-tshift --tier standard --out docs/validation   # needs the AFNI oracle (scripts/build_afni_oracle.sh)
(cd crates-gpl && cargo build --release)   # the GPL replica, run as a separate program
python -m larmorx_validation parity afni-tshift --tier standard --implementation replica --out docs/validation
python -m larmorx_validation parity afni-automask --tier standard --out docs/validation   # the AFNI oracle and the larmorx-gpl build
python -m larmorx_validation parity afni-unifize --tier standard --out docs/validation
python -m larmorx_validation parity resample-series --tier standard --out docs/validation   # needs fmriprep, nitransforms, scipy in the environment
python -m larmorx_validation parity numpy-linalg --tier standard --out docs/validation   # needs numpy on the Haswell kernels, threadpoolctl, sdcflows
python -m larmorx_validation.parity.numpy_linalg kernels --n 200000 --kernels Haswell SandyBridge Nehalem Prescott --out docs/validation/numpy-linalg-kernels.json
python -m larmorx_validation parity ants-image-math --tier standard --out docs/validation   # these need the ANTs oracle (scripts/build_ants_oracle.sh)
python -m larmorx_validation parity ants-threshold-image --tier standard --out docs/validation
python -m larmorx_validation parity ants-multiply-images --tier standard --out docs/validation
python -m larmorx_validation parity ants-smooth-image --tier standard --out docs/validation
python -m larmorx_validation parity ants-resample-image-by-spacing --tier standard --out docs/validation
python -m larmorx_validation parity ants-resample-image --tier standard --out docs/validation
scripts/build_crmath_preload.sh   # ANTs with correctly rounded math, the N4 suite's exact reference
python -m larmorx_validation parity ants-n4 --tier standard --out docs/validation   # about two hours (ANTs at six thread counts)
python -m larmorx_validation parity ants-denoise --tier standard --out docs/validation   # about an hour (ANTs at four thread counts on whole T1w images)
python -m larmorx_validation.parity.mri_hmc_band --mcflirt ~/fsl/bin/mcflirt   # mcflirt's variability band (needs FSL)
python -m larmorx_validation parity mri-hmc --tier standard --out docs/validation   # needs the recorded mcflirt runs
python -m larmorx_validation pipeline-stages --oracle <workspace>/oracles/fmriprep-25.2.6/ds000005-sub-01-noreconall --out docs/validation   # needs the fMRIPrep oracle run (scripts/run_fmriprep_oracle.sh), its image and Apptainer; about an hour
```
