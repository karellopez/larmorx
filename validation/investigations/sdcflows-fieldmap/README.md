# sdcflows' field-map estimation (field maps, part A)

The tools behind the port of sdcflows 2.17.1's field-map estimation (`crates/larmorx-sdcflows`,
`lx.sdcflows`). Sources read (permissive; kept in `<workspace>/tags/`, sdists from PyPI with their
SHA-256 checked against PyPI's): sdcflows 2.17.1 and 2.15.1 (fMRIPrep 25.2.6's), scikit-learn 1.9.1
and 1.6.1, SciPy 1.15.3 and 1.18.1, OpenBLAS 0.3.30 and 0.3.34, numpy 2.5.4.

| Tool | What it shows | Run |
|---|---|---|
| `oracle_nodes.py` | the sdcflows nodes fMRIPrep 25.2.6 ran in the oracle runs (phase-difference, phase1/phase2 and TOPUP estimators; fMRIPrep's reconstructions), with their parameters, durations and input grids: every `bs_filter` with spacing (16, 16, 10) mm, median recentring, alpha 1e-4, `zooms_min` 1, extrapolation; 9 to 118 s each | `python -P oracle_nodes.py` |
| `probe_colmat.py` | how sdcflows' collocation matrix is stored: scipy's `kron` stores a right operand densely (explicit zeros) when it fills half its matrix, and `hstack(...).tocsr()` keeps them, rows sorted | `python -P probe_colmat.py` (in each kept environment) |
| `check_weights.py` | `lx.sdcflows.bspline_grid` and `collocation_matrix` against sdcflows' `bspline_grid` and `sparse_hstack([grid_bspline_weights(...)]).tocsr()`, every array byte for byte, and the products `X @ v`, `X.T @ y` against scipy's: 15 cases (orientations, permuted axes, two levels, a single slice and row, dense axes, an oblique grid, float64, a rotated target with sdcflows' warning, a target beyond the knots, four oracle runs' field maps): all identical in the newest environment (SciPy 1.18.1, numpy 2.5.4) and the shared one (SciPy 1.15.3, numpy 2.3.5), 2026-11-08 | `OPENBLAS_CORETYPE=Haswell PYTHONPATH=<repo>/python python -P check_weights.py` |
| `check_ridge.py` | the ridge solver, bit for bit: numpy's float32 `np.dot` / `np.linalg.norm` (OpenBLAS's Haswell `sdot`; a one-element vector is numpy's plain product) on 80 vectors (lengths 0 to 10^6, signed zeros, subnormals, inf, NaN); SciPy's `cg` on 8 sparse systems (rtol, atol, maxiter 0/1/5, a zero right-hand side); scikit-learn's `Ridge(fit_intercept=False)` on 10 sparse matrices (normal equations, the kernel system with `max_iter` ignored, unsorted and duplicate indices, CSC input, float64 y, alpha 0) and its 13 messages; the B-spline fit of 5 synthetic fields (two levels, a kernel-system grid, a single slice) and of the 7 `bs_filter` field maps of the oracle runs (ds005454, ds002422 x2, ds001600 x3, ds002603's 2,097,152 x 9,072 matrix), at 1 and 14 threads: all identical in the newest and the shared environments, and identical to the coefficients fMRIPrep 25.2.6 wrote (scikit-learn 1.6.1, SciPy 1.15.2, numpy 2.2.6), 2026-11-08; scikit-learn 1.9 to 28 s, larmorx 0.3 to 3.8 s (14 threads) | `OPENBLAS_CORETYPE=Haswell PYTHONPATH=<repo>/python LARMORX_WORKSPACE=<workspace> python -P check_ridge.py [--quick]` |
| `check_approx.py` | the core of `BSplineApprox` (`_core.sdcflows_bspline_approx`: centring, the fit, the field, the error, the extrapolation, the log records, a failed fit's `RuntimeError`) against sdcflows' nipype interface run in a temporary directory, on the inputs loaded as sdcflows loads them (with a resize, the resampled grid from sdcflows' own `resample_to_zooms`): 16 synthetic cases (median, mean, mode and no centring; no mask, a full mask, a scaled int16 mask; two levels; alpha; no extrapolation; a kernel-system grid; a single slice; an odd LAS grid; two resizes; a failed fit) and the 7 `bs_filter` calls of the oracle runs; coefficients, grids, field, error and extrapolated field as stored, the intercept, every INFO and DEBUG record: all identical in the newest and the shared environments, 2026-11-08 | `OPENBLAS_CORETYPE=Haswell PYTHONPATH=<repo>/python LARMORX_WORKSPACE=<workspace> python -P check_approx.py [--quick]` |
